## PVE 页面模型下拉只有"部署默认模型"的根因与修复（11:15）

**根因（pve-host/src/index.ts 的 listModels Remote，233-254 行）**：`llm.listConfigurableProviders()` 返回 `LlmConfigurableProvider[]`，字段是 **`provider`（路由 key）/displayName/settingsNs/settingsPath**，**没有 `id` 字段**。代码用 `provider.id` 取名字 → 恒为 undefined → `llm.listModels(undefined)` 抛错被 catch 吞 → groups 恒空 → 前端下拉只剩默认模型。用户 settings.yaml 其实配了 llm-deepseek + llm-pi-ai(xinlicloud/ark-coding/hy3)。

**修复**：3 处 `provider.id` → `provider.provider`，类型断言 `{ id: string }[]` → `{ provider: string }[]`。只改 host 内部实现，Remote 协议签名未变，client 面无需重建。build:lib:host 已过，lib/index.js 产物含修复（618/620 行验证）。

**经验**：`listConfigurableProviders()`/`registerConfigurableProviders()` 的目录条目字段名是 `provider` 不是 `id`；`listModels(provider)` 要求 provider 有激活路由（settings 配了 profile），dormant provider 调它必抛错，遍历时 catch 跳过是正常设计。
